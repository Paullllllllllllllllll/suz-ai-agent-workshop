# A synthetic dataset, generated from a codebook

From the SUZ AI Agent Workshop, 8 September 2026 — the afternoon demo block.

This is a worked example of building a synthetic dataset **properly**: not by
asking a model for rows, but by writing down the data-generating process and
then implementing it. The distinction is the whole point of the block:

    codebook  ->  generator  ->  data          never   rows -> data

Rows asked for directly are shaped like data and carry no structure you chose.
A dataset built from a written specification is reproducible, auditable, and
arguable — you can disagree with any number in the codebook, which you cannot
do with a prompt.

## What is here

| | |
|---|---|
| `CODEBOOK.md` | The specification. Sample, variables, target marginals, the generating process, missingness, what structure is deliberately built in, and the validation the generator has to pass. |
| `generate_mobility.py` | The generator, written against that codebook. |
| `mobility_2026.csv` | Its output — 2400 rows, so you can look without running anything. |

## Running it

Needs `numpy` and `pandas`.

```bash
python generate_mobility.py
```

About a second. The seed is fixed, so you get a byte-identical file every time —
that reproducibility is most of the argument for working this way.

```bash
python generate_mobility.py --reveal     # adds the recovery check
python generate_mobility.py --n 500      # a smaller run
```

## What to look at, if you only have five minutes

- **§6 of the codebook**, the generating process. Every variable is sampled from
  named variables that came before it, in order. That ordering is what makes the
  structure defensible rather than incidental.
- **§8**, what is deliberately built into the data — a gender gap that reverses
  by cohort once you condition on working hours, a bad control, and missingness
  that is not uniform. Real data has structure like this; synthetic data only
  has it if you put it there on purpose.
- **The validation block** the generator prints. It checks its own output against
  the codebook, including whether the structure it was supposed to build is
  actually recoverable from the result. A generator that does not check itself is
  just a prompt with extra steps.

## The honest limits

This tests a pipeline, not a population. It is a good way to check that your
recodes fire, your analysis runs, and your instrument produces something
analysable before you spend real respondents on it. It is not evidence about
people, and no result from it is a finding.
